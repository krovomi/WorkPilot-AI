# F134 · Le smoke test Electron mourait par intermittence en SIGILL après WORKPILOT_SMOKE_OK

- **Sévérité** moyenne · **trouvé par** les CI rouges du 31 octobre (#587, #594, F133) ·
  **corrigé par** ce lot
- **Preuve** (avant) : la CI imprimait `WORKPILOT_SMOKE_OK`, puis 2 à 5 s plus tard
  `failed (exit code null, signal SIGILL)`. Reproduit en local dans les conditions du runner
  (HOME vierge, pas de CLI `claude`, venv à créer) : 4 SIGILL sur 106 lancements sous `xvfb-run`.
  Les trois core dumps, lus avec les symboles d'Electron 45, donnent la même pile :
  `InspectableWebContents::SetIsDocked` → `InspectableWebContentsView::ShowDevTools` →
  `views::WebView::SetWebContents` → `NativeViewHostAura::AttachNativeView` (`IMMEDIATE_CRASH`).
  Le front des DevTools, ouvert par `openDevTools({ mode: "right" })` dès que l'app n'est pas
  packagée, finit de charger et demande à s'ancrer alors qu'`app.exit()` a déjà fermé la
  fenêtre ; le processus principal est encore là parce que la fermeture attend le travail du
  démarrage (requête npm, pip). Quand la CI passait, des processus `python` orphelins restaient :
  `app.exit()` saute `will-quit`, où `PythonEnvManager` nettoie, et `ensurepip`, la vérification
  des dépendances et `pip install` n'étaient de toute façon pas suivis.
- **Correction** :
  - `smoke-test.ts` : un succès quitte par `app.quit()`, le chemin d'un utilisateur ; un échec
    sort toujours tout de suite avec le code 1.
  - `index.ts` : pas de DevTools pendant le smoke test, qui représente l'app livrée.
  - `python-env-manager.ts` : chaque étape du bootstrap passe par `spawnTracked`, que
    `cleanup()` tue ; après `cleanup()`, aucune étape ne démarre plus.
- **Après** : 150 lancements sur 150 verts dans les mêmes conditions, sans orphelin.
- **Garde-fous** : `src/main/__tests__/smoke-test.test.ts` (succès = `app.quit()`),
  `src/main/__tests__/python-env-manager-shutdown.test.ts`, et le smoke test de la CI.
