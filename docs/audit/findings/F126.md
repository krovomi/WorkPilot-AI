# F126 · Une installation neuve annonçait un compte Claude expiré

- **Sévérité** moyenne · **trouvé par le test E2E du premier lancement (lot N3)** · **corrigé**
- **Preuve** (avant) : `createDefaultData` (`claude-profile-manager.ts`) crée le profil « Primary »
  avec un dossier de configuration vide. Au démarrage, `getAllProfilesUsage` marquait tout profil
  sans identifiants comme à reconnecter, et `use-reauth-notifications.tsx` affichait le toast
  « Reconnection required » (« le compte a expiré ») sur une installation neuve. Mesuré depuis le
  vrai main : `requestAllProfilesUsage()` rendait `needsReauthentication: true` pour `primary`.
- **Correction** : `hasSignedInBefore` (`profile-utils.ts`) dit si un profil a déjà été connecté
  (e-mail relevé à la connexion, abonnement relevé à chaque démarrage qui trouve des
  identifiants, jeton OAuth direct). Les sept endroits du moniteur qui lisaient des identifiants
  absents passent par `flagMissingCredentials` : l'alerte pour un profil déjà connecté, rien pour
  un profil jamais connecté. Un jeton refusé ou rafraîchi sans être enregistré lève toujours
  l'alerte.
- **Limite** : un profil connecté dont ni l'e-mail ni l'abonnement n'ont pu être relevés ne lève
  plus l'alerte s'il perd ses identifiants ; les Comptes le montrent toujours non connecté.
- **Garde-fou** : `usage-monitor-reauth.test.ts` (profil connecté : alerte ; jamais connecté :
  aucune, y compris au démarrage) et `e2e/first-run.e2e.ts` (« a fresh install raises no
  re-authentication alarm », rouge sur l'ancien code).
