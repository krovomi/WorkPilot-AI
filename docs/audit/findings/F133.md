# F133 · Une tâche qui ne change qu'un fichier texte échouait en QA après avoir brûlé des dizaines de milliers de jetons

- **Sévérité** haute · **trouvé par** Leub (2026-10-31, tâche « Create toto.txt file at project
  root ») · **corrigé par** la PR « revue QA légère pour les changements texte »
- **Preuve** (avant) : `qa_signoff.coverage` absent ou `measured: false` → `evaluate_coverage`
  rejette à 100 % ; 3 passes à l'effort `none` → « QA gave up after 3 review passes ». Prompt QA
  de 24 851 caractères sur le dépôt WorkPilot ; `grep -rE "(password|secret|api_key|token)…" .`
  à la racine d'un projet avec `node_modules` : 707 Ko de sortie, `grep -r "eval(" …` : 955 Ko.
- **Correction** : `change_scope()` classe le diff (commité, non commité, non suivi) depuis la
  base ; `light` seulement si tous les fichiers sont `.txt/.md/.rst/.adoc` ou README/LICENSE…,
  ≤ 10 fichiers et ≤ 400 lignes. La passe légère utilise `qa_reviewer_light.md` (3,5k
  caractères), `use_subagents=False`, ni mémoire ni patterns appris, et la barrière de
  couverture ne s'applique pas. `WORKPILOT_QA_LIGHT=0` revient à la revue complète.
- **Garde-fou** : `test_a_text_only_task_is_not_rejected_by_the_coverage_gate` (échoue avec
  `WORKPILOT_QA_LIGHT=0`), `test_a_code_change_still_meets_the_coverage_gate`,
  `tests/test_change_scope.py`.
