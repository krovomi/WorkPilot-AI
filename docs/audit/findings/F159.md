# F159 · Le README et ses guides décrivaient des providers, variables et commandes que le code n'a pas

- **Sévérité** moyenne · **trouvé par** la relecture du README contre le code demandée par Leub
  (2026-11-07).
- **Preuve** (avant) :
  - providers : Azure OpenAI listé alors que ni `capabilities/providers.yaml` ni
    `config/configured_providers.json` ne le connaissent ; Mistral, DeepSeek, Windsurf, LM Studio et
    les CLI (Codex, OpenCode, Antigravity, pi, Gemini CLI) absents du tableau ;
  - variables : `ANTHROPIC_API_KEY` (exclu par `core/auth.py`), `XAI_API_KEY` (le code lit
    `GROK_API_KEY`), `AZURE_OPENAI_*` ;
  - commandes : `pnpm run test:all` présenté comme la suite complète alors que
    `scripts/pre-push.js` sans `--full` ne joue que le lint ; `curl http://127.0.0.1:9000` sans
    route (`/health` existe) ; Claude Code installé par `pnpm add -g` alors que l'app utilise
    l'installeur natif ;
  - versions : pnpm 12.5.1 (épinglé 12.16.1), Node « ≥ 20 » ou « 24+ » (Vitest 5 exige 22.12+),
    Python 3.9+ dans le guide CLI (`run.py` exige 3.12) ;
  - chemins : `apps/backend/subagents/` décrit sous `agents/`, `apps/backend/skills/` inexistant,
    `specs/…/PAUSE` et `.worktrees/` au lieu de `.workpilot/specs/` et
    `.workpilot/worktrees/tasks/`, `tests/pytest.ini` au lieu de `pytest.ini` ;
  - contenu : détection de stack et « Design to Code » réduits à React/Python, notifications
    « email » (les canaux sont Slack, Teams, Discord, Google Chat, webhook), phases des niveaux de
    complexité (3/6/8 au lieu de 4/7/9), vues expérimentales présentées comme stables.
- **Correction** : documentation seulement ; aucune ligne de code modifiée.
