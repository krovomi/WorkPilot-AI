# F173 · Le premier lancement et l'ajout d'un projet butaient sur huit bugs, de l'assistant au premier commit

- **Sévérité** haute · **signalé** par Leub le 2026-11-09 (« j'ai l'impression qu'il y a des bugs
  lorsque l'on arrive la première fois et qu'on paramètre WorkPilot-AI ainsi que lorsqu'on met un
  projet »).
- **Méthode** : l'app construite, lancée sous xvfb avec Playwright sur un HOME et un profil vierges,
  sans `claude` dans le PATH ni identité git ; assistant parcouru par chaque chemin (OAuth, clé
  d'API, Passer, Créer une tâche), puis ajout de projets .NET, Python, React, Go, Rust, Java,
  Flutter et PHP : dépôt avec commit, sans commit, dossier sans git, chemin avec espace et accent,
  création d'un projet neuf.

## Assistant de premier lancement

1. **Libellé brut `steps.claudeCode`** dans la barre de progression : la clé est `steps.cli`. Les
   étapes vivent dans `wizard-steps.ts`, un test vérifie chaque clé en `en` et en `fr`.
2. **« Authentifié » sans connexion** : `OAuthStep` comptait `isDefault && configDir`, vrai pour le
   profil par défaut (`~/.claude`) avant toute connexion ; « Continuer » s'activait et la première
   tâche échouait ensuite. L'état vient maintenant de `isAuthenticated`, calculé par le main
   (`isProfileSignedIn` dans `first-run.ts`).
3. **Le chemin clé d'API ne passait jamais l'étape OAuth** : le test du nombre de profils lisait une
   valeur capturée avant l'enregistrement. `ProfileEditDialog.onSaved` déclenche le saut.
4. **« Passer » terminait l'assistant** aux étapes Authentification et CLI : sans compte Claude,
   l'utilisateur ne voyait jamais les outils de dev ni la confidentialité. « Passer » saute l'étape.
5. **« Ouvrir le créateur de tâches » sans projet** : le créateur n'est monté qu'avec un projet, rien
   ne s'ouvrait, et `onboardingCompleted` n'était pas enregistré (l'assistant revenait au lancement
   suivant). L'assistant est terminé, et sans projet c'est l'ajout de projet qui s'ouvre.

6. **Indicateur d'usage bloqué sur « Loading... »** : il attend un fournisseur, et seul le sélecteur
   de Réglages → Général en choisit un. Sans choix, une fois les réglages lus, il suit le profil
   d'API actif, sinon Anthropic, comme le badge d'authentification voisin
   (`hooks/useEffectiveUsageProvider.ts`).

## Ajout d'un projet

7. **Identité git absente** (machine neuve) : « Initialiser Git » s'arrêtait sur « Author identity
   unknown ». `initializeGit` demande à git (`git var GIT_AUTHOR_IDENT`, indépendant de la langue) et
   renvoie le blocage `git-identity-missing` ; la fenêtre git et les réglages du projet affichent un
   formulaire nom/e-mail, enregistré en `git config --global` (les commits des agents en ont besoin
   aussi) après revalidation dans le main (`parseGitIdentity` : une ligne, pas de `<>`, e-mail
   plausible).
8. **Création d'un projet** : « Suivant » restait grisé tant qu'on ne recliquait pas sur « Passer
   pour l'instant », pourtant affiché comme choisi ; puis la modale d'ajout et la barre latérale
   ouvraient chacune une fenêtre git, et la seconde fermait les réglages qui initialisent le projet.
   Le formulaire complet suffit, le récapitulatif montre le dossier réellement créé, et un projet à
   initialiser répare git dans ses réglages (« Préparer le dépôt et initialiser »), en un seul
   endroit.
