# F179 · Le studio de génération de tests échouait sur « No agent runtime is installed », sur tous les providers

- **Sévérité** haute · signalé par Leub le 2026-11-09 (projet .NET xUnit, app lancée depuis les
  sources sous WSL) : « Lorsque je veux générer des tests, cela ne marche pas », puis « ni pour
  Analyser, E2E et TDD ».
- **Preuve** (avant) : `TestGeneratorAgent._call_llm` lève `DetailedError("No agent runtime is
  installed (core is not imported).")` quand `agent_runtime.current()` vaut `None`. Le runner
  n'importait que `foundation` et `test_generation`, qui n'importent pas `core` (contrat
  d'imports), donc le port n'était jamais installé dans ce processus. Les actions sans modèle
  (choix du dossier, des bibliothèques, ajout des paquets) marchaient, d'où une panne visible
  seulement au moment de générer.
- **Correction** : `import core` dans `main()` du runner, avant l'import du générateur.
- **Chemin E2E** : vérifié de bout en bout (projet xUnit, provider Ollama simulé), l'onglet E2E
  écrivait `e2e/test_calculator.js` quand la réponse n'avait pas de chemin, car le repli de
  `_parse_generation_result` ne connaissait que `.py` et `.js`. Il prend maintenant
  `suggested_test_path(langue, nom, "e2e")` (`e2e/CalculatorE2ETests.cs`), et garde le chemin du
  modèle quand la convention de la stack n'a pas de dossier `e2e` (Ruby, Dart, PHP…).
- **Garde-fous** : `tests/test_agent_runtime_port.py` vérifie que tout runner qui importe une
  unité du port importe aussi `core`, et lance `test_generation_runner.main()` dans un
  sous-processus pour `analyze-coverage`, `generate-unit`, `generate-e2e` et `generate-tdd` :
  le runtime installé doit être `CoreAgentRuntime` quand l'action démarre.
  `tests/test_test_generator.py` couvre le chemin E2E de C#, Java, Go et Ruby.
