# F147 · Lancement de l'app noyé sous les avertissements et les détections en double

- **Sévérité** faible · **trouvé par** Leub (2026-11-02), log de `pnpm dev` à l'appui ·
  **corrigé par** la PR « nettoyer les logs au lancement »
- **Preuve** (avant) : `SETTINGS_GET` appelait `configureTools` puis `preWarmToolCache(["claude"])`
  à chaque lecture des réglages ; `encryptSecret` rechiffrait chaque secret inchangé à chaque
  écriture de `settings.json` ; `cli/__init__.py` importait `cli.main`, que le serveur de streaming
  lance avec `python -m cli.main` ; `init_database` appelée par le lifespan et par le montage du
  routeur analytics.
- **Correction** : crypto `safeStorage` asynchrone en amont des lecteurs synchrones
  (`initSecretStorage`, `prepareSecrets`, cache dans les deux sens) ; `configure` sans effet sur
  une configuration identique et détections asynchrones partagées ; `coalesceInFlight` sur les
  vérifications de version Claude Code, Copilot et de mise à jour ; commandes fixes sans tableau
  d'arguments quand `shell: true` ; `cli.main` chargé à la demande ; `init_database` idempotente ;
  journaux d'information derrière `DEBUG=true`.
- **Non traité** : l'erreur `WebGL1 blocklisted` vient du process GPU de Chromium (GPU sur liste
  noire sous WSLg) ; la taire demande de baisser le niveau de log de Chromium entier, ce qui
  masquerait aussi les vrais plantages GPU.
