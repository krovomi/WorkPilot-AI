# F127 · Rien n'empêchait d'ajouter une erreur avalée, un biome-ignore ou une erreur de type

- **Sévérité** moyenne · **trouvé par le plan du 29 octobre (Q1, Q2, Q3)** · **atténué par le lot N4**
- **Preuve** (avant) : 1 533 gestionnaires aveugles dans 492 fichiers suivis de `apps/backend/`,
  dont 226 qui ne font que `pass`, `...` ou `continue` ; 770 `biome-ignore` dans 277 fichiers de
  `apps/frontend/` ; ni mypy ni pyright dans un workflow. pyright `basic` trouvait 22 erreurs dans
  les sept paquets « feuilles » (`bench`, `best_of_n`, `genai_trace`, `goal`, `mcp_tasks`,
  `os_sandbox`, `security`) et les modules qu'ils importent : `Optional` non vérifié avant `/`,
  `Popen` typé `str` au lieu de `bytes`, attributs propres à Windows, `rich` possiblement absent.
- **Correction** :
  - `scripts/quality_baselines.py` compte, par fichier suivi, les `except` aveugles (et parmi eux
    les muets) et les `biome-ignore` ; `tests/baselines/*.json` garde le plafond de chaque
    fichier, une ligne par fichier pour que deux PR qui corrigent deux fichiers ne se
    contrarient pas. `update` ne fait que baisser et n'ajoute jamais de fichier ; un relèvement
    s'écrit à la main dans le JSON, visible en revue.
  - Les 22 erreurs pyright corrigées sans changer de comportement (garde explicite là où une
    propriété garantissait déjà la valeur, arguments de `Popen` écrits au lieu d'un `**options`,
    `# type: ignore[attr-defined]` sur les seuls attributs Windows). `pyrightconfig.json` liste
    les paquets ; le job `types` de `lint.yml` installe pyright `1.1.408`, épinglé comme ruff.
- **Reste** : les comptes eux-mêmes. Le plafond arrête la croissance, il ne corrige rien.
- **Garde-fou** : `tests/test_quality_baselines.py` (plafond dépassé, plafond à baisser, comptage,
  `update` qui ne monte jamais), `tests/test_tool_pins.py` (pyright de la CI = celui des règles),
  le job `Python (pyright)` dans `Lint Complete`, le hook pre-push (`quality:baselines`).
