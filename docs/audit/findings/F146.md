# F146 · Un run serveur interrompu restait « en cours » pour toujours, et Stop ne pouvait pas arrêter un run en file

- **Sévérité** haute · **trouvé par** le scan des features demandé par Leub (2026-11-02).
- **Preuve** (avant) : `RunManager` n'avait pas d'équivalent de `ProjectJobs.settle_orphans` ;
  `count_active_runs` (quotas) comptait les runs fantômes ; `cancel_run` renvoyait `False` sans
  processus ; `availableActions` (mobile) renvoyait `["stop"]` pour toute colonne active.
- **Correction** : `RunManager.settle_orphans()` au premier accès à la base du processus, runs
  suivis (`_tracked`), annulation d'un run en file avant son démarrage ; mobile : « Relancer »
  sur une colonne active sans run, Stop qui dit quand il n'y avait rien à arrêter, sondage
  de la carte sans spinner de rafraîchissement.
