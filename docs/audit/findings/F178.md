# F178 · La boucle d'apprentissage n'appelait aucun modèle, sur aucun provider

- **Sévérité** moyenne · demandé par Leub le 2026-11-09 (« brancher tous les providers, que cela
  fonctionne peu importe le provider sélectionné »).
- **Preuve** (avant) : `LearningLoopService._run_analysis` n'appelait que `_heuristic_extract`
  (docstring de F131) ; `PatternExtractor.model` valait `sonnet` par défaut, et
  `learning_loop_runner.py --model` aussi.
- **Correction** : `learning_loop/model_analysis.py` (`extract_with_model`, `vet_patterns`),
  appelé par `_run_analysis` ; modèle `None` par défaut (celui du provider) ; le runner importe
  `core`, qui installe le port ; `learning_loop` peut importer `agent_runtime`
  (`tests/test_import_contracts.py`).
- **Garde-fous** : ce que le modèle écrit devient une consigne dans les prompts suivants. Le prompt
  système dit que les enregistrements sont des données (règle 4) ; un pattern dont la description
  ou la consigne est jugée suspecte ou bloquée par `security.untrusted` est écarté, et chaque
  pattern reste désactivable dans le tableau de bord.
