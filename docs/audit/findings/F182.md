# F182 · La barre « Commande rapide » échouait avec un abonnement Claude, ignorait le provider choisi et écrivait dans le dossier du projet

- **Sévérité** haute · signalé par Leub le 2026-11-09 (abonnement Claude classique, profil
  « Primary », app lancée depuis les sources sous WSL) : « Échec de la commande — command run
  failed: No OAuth token found. WorkPilot AI requires Claude Code OAuth authentication. Direct API
  keys (ANTHROPIC_API_KEY) are not supported. » Il demande aussi que les commandes marchent quel
  que soit le provider sélectionné, pas seulement Claude Code.
- **Cause** : le main lance le serveur backend (`uvicorn provider_api:app`) une seule fois, avec
  `process.env`. Les profils Claude de WorkPilot sont isolés (`~/.claude-profiles/<profil>`,
  `CLAUDE_CONFIG_DIR`) : le main ne les passe qu'aux processus qu'il lance pour une tâche ou une
  page. Le serveur cherchait donc le jeton dans `~/.claude`, vide sous WSL. Pour la même raison,
  `SELECTED_LLM_PROVIDER` n'y était jamais : `peek_active_provider` retombait sur le défaut
  `claude`. L'agent `coder` recevait enfin `project_dir` = le dossier du projet.
- **Correction** : `runQuickCommand` (main) refuse un projet qui n'est pas local et un nom de
  commande qui serait un chemin, ouvre la carte « Commande rapide : /x » (`openReviewRun`),
  lance le runner avec `pythonRunnerEnv`, puis commite (`recordReviewStep`) que la commande ait
  réussi ou échoué. Une commande à la fois par projet. `/help` est répondu par la barre ;
  `/review` a des instructions que tout provider exécute. La barre affiche la réponse et, si des
  fichiers ont été écrits, la carte et sa branche ; la carte apparaît en Revue humaine.
- **Vérification** : `pytest tests/test_slash_command_runner.py -q` ;
  `cd apps/frontend && pnpm test -- quick-command-run QuickCommandBar ipc-channel-parity`.
