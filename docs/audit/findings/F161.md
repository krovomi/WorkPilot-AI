# F161 · Visuel vers Code ne disait pas pourquoi un lien était refusé, ni ce qui clochait sur le schéma entier

- **Sévérité** moyenne · **trouvé par** Leub (2026-11-07) : « il faut que chaque bloc ait des
  cohérences entre eux en se basant sur les règles d'architecture applicatives, de code et autres
  règles connues ».
- **Preuve** (avant) : `canConnect` répondait oui ou non ; la notification de F160 disait seulement
  « ne prévoient pas ce lien ». Aucune règle ne portait sur les stacks ni sur le schéma complet.
- **Correction** :
  - `connection-verdicts.ts` : rôle de chaque type (client, point d'entrée, CDN, service, worker,
    stockage, messagerie, identité, tiers, livraison, observation) et une raison par famille de
    paires refusées, avec les blocs à intercaler ; un test vérifie qu'aucune des 361 paires ne tombe
    sur la raison générique. Paires ajoutées : client lourd → file, gateway → stockage, worker → CDN,
    broker → recherche / base / stockage (connecteurs sink), réplication cache et stockage, identité →
    file, notification → backend (webhook de statut), analytics → outil tiers ;
  - `stack-rules.ts` : Celery (RabbitMQ, Redis, SQS), BullMQ et Sidekiq (Redis), job mis en file
    depuis son propre langage, base locale du mobile (SQLite), SQLite côté serveur, Elasticsearch /
    OpenSearch jamais exposés au client, push impossible par SendGrid / SMTP / Twilio, CDN sur disque
    local, état partagé des workers hors Memcached, YARP pour des fichiers statiques ;
  - `architecture-lint.ts` : une base par microservice, pas de cycle d'appels synchrones, un seul
    point d'entrée quand une gateway existe (BFF conseillé au-delà de trois services appelés),
    client lourd qui écrit la base et appelle le backend, file sans consommateur ou sans producteur,
    stockage sans propriétaire, identité inutilisée, worker sans déclencheur, bloc isolé, liens
    forcés ;
  - interface : « Inverser le sens » dans la notification, panneau « Points d'attention » dans la
    barre d'état (un clic sélectionne les blocs concernés), avertissements de stack dans
    l'inspecteur ; section « Points d'architecture à régler » dans la spécification de build.
