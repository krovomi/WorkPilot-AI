# F139 · Scripts ponctuels, configurations en double et ressources que rien ne lisait

- **Sévérité** basse · **trouvé par** le scan de nettoyage demandé par Leub (2026-11-02,
  « je veux une codebase très propre ») · **corrigé par** la PR « nettoyage : restes du dépôt »
- **Preuve** (avant) : pour chaque fichier, `git grep` de son nom (avec et sans extension) dans
  tout le dépôt, `pnpm-lock.yaml` exclu ; seuls appelants trouvés : la ligne de
  `scripts/README.md` qui le décrivait. Git n'exécute que le hook nommé exactement `pre-commit`,
  jamais `pre-commit.bat`. `core.hooksPath` vaut `.husky` à la racine : `apps/frontend/.husky/`
  ne tournait pas, et avec lui lint-staged. `config/.gitattributes`, `.gitmodules`, `.npmrc`,
  `.coderabbit.yaml` ne sont lus qu'à la racine du dépôt.
- **Correction** : fichiers supprimés ; `scripts/README.md`, `apps/frontend/README.md` et
  `package.json` mis à jour ; lockfile régénéré.
- **Garde-fou** : `tests/test_scripts_readme.py` (une ligne par script, un script par ligne),
  `pnpm run validate:npm-scripts`.
