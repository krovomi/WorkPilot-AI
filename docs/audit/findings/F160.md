# F160 · Visuel vers Code refusait des connexions cohérentes et n'offrait qu'un champ libre pour la relation

- **Sévérité** moyenne · **trouvé par** Leub (2026-11-07), capture « Connexion non valide » sur
  BackEnd DotNet → Worker DotNet.
- **Preuve** (avant) : `RELATIONS` de `architecture-connections.ts` ne prévoyait aucune liaison
  Backend → Worker, refusait volontairement Worker → Database, et `canConnect` rejetait toute paire
  absente, sans possibilité de forcer. Le champ « Relation » de l'inspecteur était un `Input` libre.
- **Correction** :
  - règles : table réécrite par rôle (clients, services, données, messagerie, infra, sécurité,
    intégrations), avec les liaisons manquantes (déclenchement de jobs, push temps réel, webhooks,
    CDC, réplication, lettres mortes, événements de stockage, alertes, micro-frontends, base locale
    du mobile) ; tout bloc typé peut remonter vers le monitoring ;
  - relations : `connection-protocols.ts` propose, par type d'interaction et par stack, les
    protocoles et bibliothèques usuels (.NET, Java/Kotlin, Node, Python, Go, Rust, PHP, Ruby,
    Flutter, Swift, React Native, MAUI…), testés pour chaque stack de la palette ;
  - interface : liste déroulante + « Autre (saisie libre)… » ; une paire imprévue affiche
    « Connexion inhabituelle » avec « Relier quand même », et le fil forcé est dessiné en pointillés.
