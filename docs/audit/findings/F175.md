# F175 · Supprimer un projet serveur laissait tourner ses agents, et SQLite ignorait les suppressions en cascade

- **Sévérité** haute · **trouvé** au tri du 2026-11-09 (develop `ea5db86`), signalé dans la revue du
  2026-11-02 sans être traité.
- **Preuve** (avant) : `delete_project` appelait `db.delete(project)` puis `delete_clone(project_id)`
  sans regarder `RunManager` ni `ProjectJobs` ; aucun `PRAGMA foreign_keys` dans `apps/backend/server`.
- **Correction** : `stop_project()` dans les deux gestionnaires (annule chaque run ou job du projet,
  attend qu'il ait fini), appelé par la route avant toute suppression ; écouteur `connect` qui active
  le pragma dans `server/db/engine.py`.
- **Effet de bord voulu** : les tests serveur qui écrivaient des lignes pointant vers des
  utilisateurs inexistants (`u-1`, `u1`, `u-owner`) créent désormais ces utilisateurs, comme
  PostgreSQL l'exigeait déjà.
