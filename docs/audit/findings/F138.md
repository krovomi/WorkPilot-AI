# F138 · Une tâche sans changement de code faisait fabriquer de faux projets de tests au correcteur QA

- **Sévérité** haute · **trouvé par** Leub (2026-11-01, tâche « Créer un fichier tutu.txt et
  ajoute OK dedans ») · **corrigé par** la PR « QA : pas de barrière de couverture sans code
  modifié »
- **Preuve** (avant) : `classify([], 0)` → `full` (« no file changed ») ; `_coverage_gate`
  ne sautait que pour `is_light` ; `render_coverage_fix_request` demandait « Ajouter/compléter
  les tests jusqu'à atteindre le seuil » ; diff final : `tests/Rag.Application.Tests/DummyTest.cs`,
  `tests/Rag.Domain.Tests/DummyTest.cs`, deux `.csproj`, `TESTING.md`.
- **Correction** : changement vide → revue légère avec une consigne dédiée ; `touches_code`
  (vrai si un fichier non texte a changé, ou si le changement est illisible) décide de la
  barrière de couverture, y compris avec `WORKPILOT_QA_LIGHT=0` ; consignes contre les tests
  factices dans `qa_fixer.md`, `qa_reviewer.md` et la demande de correction de couverture.
- **Garde-fou** : `test_an_empty_change_set_is_light_and_touches_no_code`,
  `test_the_coverage_gate_skips_change_sets_without_code`,
  `test_the_light_prompt_for_an_empty_change_checks_the_repository`.
