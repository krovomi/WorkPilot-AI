# F158 · Les projets WPF, WinUI, MAUI ou à Directory.Build.props n'avaient pas de version .NET

- **Sévérité** moyenne · **trouvé par** l'intégration de la skill de migration .NET 11 demandée
  par Leub (2026-11-07).
- **Preuve** (avant) : `_TFM_RE = ^net(?:coreapp|standard)?(\d+(?:\.\d+)*)$` ne laissait passer
  aucun suffixe `-windows`, `-android`…, et `_detect_dotnet` ne parcourait que `rglob("*.csproj")`.
  Une solution qui centralise `<TargetFramework>` dans `Directory.Build.props` (fréquent avec
  Central Package Management) n'avait donc pas de cible. `netstandard2.0` devenait `2.0`.
- **Correction** : `dotnet_project_files` liste les fichiers MSBuild qui peuvent porter la cible ;
  le moniker de plateforme est lu par sa partie runtime ; `netstandard` ne compte plus comme une
  version de runtime ; les sorties de build (`bin/`, `obj/`) ne sont plus lues.
- **Au passage** : `dotnet_upgrade` (docs/architecture/dotnet-upgrade.md) s'appuie sur la même
  lecture pour décider si une tâche reçoit la procédure de migration vers .NET 11.
