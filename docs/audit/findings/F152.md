# F152 · La QA ciblée ne connaissait que Python et TypeScript

- **Sévérité** moyenne · **trouvé par** l'audit des tokens des tâches Kanban demandé par Leub
  (2026-11-03), qui a demandé que l'optimisation vaille pour tous les langages frontend et
  backend.
- **Preuve** (avant) : `foundation/touched_tests.py` ne mappait que `.py` et
  `.ts/.tsx/.js/.jsx/.mts/.cts/.mjs/.cjs` ; `targeted_blocker` renvoyait « file type the
  targeted review does not map » pour un `.cs`, un `.java` ou un `.go`, donc revue complète.
- **Correction** : `foundation/test_conventions.py` porte la convention de chaque écosystème
  (.NET et Blazor, JVM, Go, Rust avec ses modules `#[cfg(test)]`, PHP, Swift, Dart/Flutter,
  Ruby, Elixir, C/C++) ; `.vue`, `.svelte`, `.astro` et les templates/styles d'un composant
  Angular se mappent sur leur test TypeScript. Le gate accepte qu'une commande nomme la classe
  (`dotnet test --filter`, `mvn -Dtest=`, `gradle --tests`, `swift test --filter`) ou le dossier
  (`go test ./pkg`) du test. Le prompt ne donne que les commandes des écosystèmes présents.
  Fichiers générés (`*.Designer.cs`, `*.g.cs`, `*.pb.go`, `*.g.dart`, `*.freezed.dart`…) et
  fichiers de portée projet (`Program.cs`, `Startup.cs`, `_Imports.razor`, `build.rs`,
  `Package.swift`, `mix.exs`, `spec_helper.rb`…) gardent la revue complète.
- **Garde-fou** : `tests/test_targeted_qa_languages.py` fixe la convention de chaque écosystème,
  ce qui n'est jamais un test (`latest/`, `SPLIT.java`, un helper de projet de test) et la preuve
  d'exécution acceptée.
