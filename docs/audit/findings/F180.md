# F180 · Des pages écrivaient le code généré directement dans le dossier du projet, sans branche ni revue

- **Sévérité** haute · signalé par Leub le 2026-11-09, après la réparation du studio de tests
  (F179) : « cela ne crée pas les nouveaux fichiers générés dans un worktree et je ne peux pas
  ouvrir de PR, comme sur le kanban. Il faudrait faire cela pour toutes les features/pages. […]
  Il me faut une relecture, et par conséquent une nouvelle PR à chaque fois. »
- **Preuve** (avant) : `_write_test_file` résout la destination sous `--project-path`, le dossier
  du projet que le renderer envoie ; `add-packages` modifie les manifestes au même endroit ;
  `DESIGN_TO_CODE_WRITE_FILES` écrit sous `project.path` ; `saveChangelog` écrit
  `CHANGELOG.md` sous `project.path` ; le pair programming lance l'agent `coder` avec
  `project_dir = project.path`.
- **Inventaire** : [`generated-review.md`](../../architecture/generated-review.md) liste les pages
  qui écrivent, celles qui passaient déjà par une carte et celles qui n'écrivent rien.
- **Correction** (lot 1, studio de tests) : chaque génération (Unitaire, E2E, TDD) et l'ajout de
  paquets écrivent dans le worktree d'une carte « Code généré » ; la carte passe en revue humaine
  avec l'exécution comme sous-tâche, et le studio affiche « Voir la carte » et « Créer la PR ».
  Lot 2 : Import Design (« Écrire sur une branche de revue », chaque chemin vérifié dans le projet
  puis dans le worktree) et le journal (« Enregistrer » commite `CHANGELOG.md` et les images
  collées sur la branche de la carte ; le chemin du fichier, joint sans contrôle jusque-là, est
  ramené dans le projet). Les lots 3 et 4 suivent.
- **Vérification** : `pytest tests/test_review_worktree_runner.py -q` ;
  `cd apps/frontend && pnpm test -- generated-review test-generation-service-errors
  design-to-code-write changelog-review renderer-path-refusals`.
