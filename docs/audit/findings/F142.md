# F142 · Orchestration multi-dépôts écrite de bout en bout, jamais branchée

- **Sévérité** moyenne · **trouvé par** le scan de nettoyage demandé par Leub (2026-11-02), qui
  a choisi de brancher la feature plutôt que de la retirer · **corrigé par** la PR « brancher le
  multi-dépôts »
- **Preuve** (avant) : `MultiRepoDialog` sans aucun import hors de son dossier ;
  `agentManager.emit("multi-repo-start", …)` sans écouteur ; `createMultiRepoOrchestration("", …)` ;
  `_run_repo_pipeline` qui rendait `True` après avoir écrit `spec.md`.
- **Correction** : `main/multi-repo/` (manifeste, déroulé testé avec un hôte factice, hôte réel) ;
  `createLocalTask` extrait de `TASK_CREATE`, `getTaskControl()` de `TASK_START` / `TASK_STOP` ;
  `TaskStateManager.addStatusListener` ; runner Python en trois sous-commandes (`analyze`, `brief`,
  `check`) ; chemins des dépôts revalidés dans le main (projet enregistré ou dossier choisi) ;
  canaux d'événements remplacés par un seul `multiRepo:updated`.
- **Garde-fou** : `tests/orchestration/test_multi_repo_runner.py`,
  `apps/frontend/src/main/multi-repo/__tests__/`,
  `apps/frontend/src/main/ipc-handlers/__tests__/multi-repo-handlers.test.ts`.
