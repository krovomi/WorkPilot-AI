01 · Vue macroscopique

Ce que WorkPilot AI exécute réellement

Une application Electron pilote un backend Python ; toute interaction LLM passe par une seule fabrique (core/client.py) qui choisit le provider, les outils, les serveurs MCP et le roster de sous-agents. Depuis l'audit précédent, chaque tâche possède son moteur par phase (#290), les tâches UI reçoivent un design system (#291) et l'application modifiée est lancée et vérifiée avant la QA (#292). Les six constats qui pèsent le plus

  1. Sept features LLM échouent toujours en silence () : leur agent_type n'existe pas ; l'extracteur d'insights, qui devait nourrir la mémoire, en fait partie.
  2. Deux features visibles ne produisent rien : la phase architecture-map tourne sous un agent en lecture seule sans le pipeline archify () ; la page Context-aware snippets n'a pas de handler IPC et son runner importe des modules inexistants ().
  3. ~67 k tokens de doc chargés à chaque session : docs/CLAUDE.md est importé par CLAUDE.md ().
  4. Une partie du pipeline payé ne s'exécute pas : cinq phases pointent vers des packs vides, trois vers BMAD qui exige _bmad/ ( ).
  5. La mémoire « unique » a encore des voisines : Graphiti en hausse, deux magasins de patterns, quatre écritures par merge ( ).
  6. ~27 k lignes sans appelant, hors Graphiti : 57 fichiers frontend (~16,5 k), 3 paquets et 12 modules backend (~6,7 k), utils/ (3,7 k) ; plus 11 prompts orphelins et 4 shims sans importeur ( ).

Ce qui est déjà sain (et l'est resté)

  • Une seule fabrique de clients ; la matrice capabilities/providers.yaml décide sous-agents, effort et famille de surcharges de skill.
  • Les nouvelles features réutilisent l'existant : verify s'appuie sur AppEmulatorRunner, mobile.stacks, docintel ; uiux sur le cerveau et la prévision du plan.
  • Les phases conditionnelles sont maintenant décidées sur les fichiers prévus par le plan (narrow_to_forecast) : une tâche backend ne paie plus les phases web.
  • Le profil affiché signale les implémentations manquantes (CLI et carte WorkflowProfileCard).
  • rtk, watermarks, read_guard, cerveau, uiux et verify sont branchés une fois : fabrique pour le SDK Claude, tool_executor pour les autres providers.

Garde-fou contourné par la configuration (). La doc fait de l'absence de hermes-learned dans [packs] la barrière qui empêche un skill écrit par un agent d'atteindre les harness sans relecture. .workpilot/skills.toml le liste toujours ; le premier skill adopté sera émis partout.

05 · Registre

Agents, rosters et sous-agents

Un agent_type fixe les outils, les serveurs MCP et le niveau de réflexion (agents/tools_pkg/models.py). Il choisit aussi, via PHASE_ALIASES, un roster de sous-agents (agents/subagents/phases.py:84). Tout ce qui n'est pas aliasé tombe sur le roster Kanban. Une phase skill sans agent déclaré tourne sous analyzer (workflows/runner.py:213).
