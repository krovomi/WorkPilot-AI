# H8 — Scénario de vérification web écrit sur la carte (IA8)

**Fait.** Le pendant web de la vérification Windows par UI Automation ([G11](G11.md)). Une carte
peut dire, en langage naturel et une étape par ligne, ce qui prouve le changement sur une
application web (`verifyScenario`, sous la boucle de vérification dans le formulaire). Le
vérificateur suit ces étapes dans le navigateur, dans l'ordre, prend une capture après chacune et
rapporte chaque étape réussie, échouée ou bloquée. Playwright pilote alors la session en premier et
garde sa trace (captures et instantanés du DOM par action), écrite dans
`verify/scenario-trace.zip`. L'onglet Vérification de la carte montre chaque étape avec sa note et
sa capture, et un lien vers la trace, à ouvrir sur trace.playwright.dev ou avec
`npx playwright show-trace`.

Une étape échouée fait échouer la vérification. Un scénario qui n'est pas allé au bout (étape
bloquée, jamais rapportée, ou pas de session de vérification) n'est jamais un succès : la
vérification passe à « inconnu », avec le nombre d'étapes réussies. Le numéro d'étape et le
résultat sont contrôlés, une capture n'est gardée que si cette vérification l'a prise, et une étape
n'élargit jamais ce que les outils permettent (les URL restent sur l'application lancée).

Justification : [`verify.md`](../../architecture/verify.md).

Vérification : `pytest tests/test_verify_scenario.py tests/test_verify_browser.py -q` ;
`cd apps/frontend && pnpm test -- VerifyLoopFields TaskVerifyScenario`.
