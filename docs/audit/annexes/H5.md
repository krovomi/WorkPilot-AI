# H5 — Le Kanban comme serveur MCP (IA5)

**Fait.** [G9](G9.md) laissait les builds hors de MCP : aucun serveur ne les exposait.
`workpilot-board` (`apps/backend/board_mcp/`, lancé par `runners/board_mcp.py --project-dir`)
sert le Kanban d'un projet à Claude Code, Codex ou Gemini CLI dans un terminal : lister les
cartes, lire une carte (colonne, sous-tâches, QA, objectif, revue croisée), en créer une dans le
backlog, attendre qu'une carte arrive dans une colonne. L'attente est une tâche MCP pour un client
qui les lit, une réponse ordinaire pour les autres.

Aucun outil ne lance un build, n'approuve un plan ni ne fusionne : ces gestes restent sur la carte,
à une personne. Le plan proposait « approuver un plan » ; il est écarté, puisque l'agent qui
l'appellerait est celui dont le plan doit être relu. Aucun outil ne prend de chemin ; un
identifiant de carte doit en avoir la forme et se résoudre dans `.workpilot/specs`. Une carte
créée est numérotée sous le verrou que l'application prend aussi.

Justification : [`board-mcp.md`](../../architecture/board-mcp.md).

Vérification : `pytest tests/board_mcp -q`.
