# H3 — Vues MCP Apps sur le chemin du SDK Claude (IA4)

**Fait.** Jusqu'ici, la vue d'un outil MCP ([G9](G9.md)) n'apparaissait dans le panneau de tâche
que pour les providers de la boucle WorkPilot : sur le SDK Claude, Claude Code est le client MCP et
n'en sait rien. Un hook `PostToolUse` (`make_app_view_hook`, `core/mcp_tools.py`), posé par
`create_client` seulement quand la session démarre un serveur de `CUSTOM_MCP_SERVERS`, ouvre après
l'appel sa propre session courte vers le même serveur, démarré comme Claude Code le démarre. Il
liste les outils une fois, lit la vue de l'outil appelé et la garde avec l'entrée et le résultat
de l'appel, par le même `capture_app_view` que la boucle WorkPilot. Le panneau, le schéma
`workpilot-mcp-app://`, la CSP et le pont ne changent pas.

Le hook ne rend rien (le résultat de l'agent est intact), n'appelle jamais un outil, ne démarre
rien pour un serveur que la session ne démarre pas, et retient l'agent au plus 20 secondes.
Justification : [`mcp-2026.md`](../../architecture/mcp-2026.md#mcp-apps-dans-le-panneau-de-tâche).

Vérification : `pytest tests/mcp_2026 -q`.
