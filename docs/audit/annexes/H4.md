# H4 — Tests d'intégration ASP.NET Core avant le code (IA6)

**Fait.** Une phase `spec-by-example`, entre `planning` et `coding` de `feature-build`, écrit les
critères d'acceptation de la spec en tests d'intégration HTTP (`WebApplicationFactory<Program>`)
avant tout code, sur une Web API ASP.NET Core. Elle ne tourne que si le projet l'active (Réglages
du projet > Général) ou la tâche (`specByExample` dans `task_metadata.json`, qui l'emporte), et
jamais quand la tâche a déjà un objectif : celui de la personne reste le sien.

Python ne croit pas la session sur parole : chaque fichier écrit doit être dans un projet de test
(ou être la solution à la racine), les tests doivent compiler, et `dotnet test` doit échouer.
Alors seulement il écrit l'objectif ([mode objectif](../../architecture/goal-mode.md)) :
`dotnet test` sur ce projet sort en 0, les fichiers de test écrits sont protégés, et la boucle QA
continue jusqu'à ce qu'ils passent. Sinon, aucun objectif, et rien n'est annulé : les fichiers
restent dans le diff. Justification : [`spec-by-example.md`](../../architecture/spec-by-example.md).

Vérification : `pytest tests/test_spec_by_example.py -q` et
`cd apps/frontend && pnpm test -- env-utils`.
