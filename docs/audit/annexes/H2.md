# H2 — Revue croisée par un second moteur avant la PR (IA2)

**Fait.** Une phase `cross-review`, après la QA de `feature-build`, `bug-fix`, `hotfix` et
`refactoring`, ouvre une session en lecture seule sur un **autre fournisseur** que celui du build,
nommé dans les réglages du projet (fournisseur × modèle × effort) ou dans `task_metadata.json`
(`crossReview`). Le relecteur lit le diff au regard de `spec.md`, du plan et de l'objectif, et
répond en JSON : `agree`, ou `disagree` avec au moins un problème `blocker` situé. Tout le reste
(pas de JSON, désaccord sans bloquant, accord avec un bloquant, session en échec) est lu
`inconclusive`, qui ne bloque rien et n'est jamais un accord (`cross_review/review.py`).

Un `disagree` retient la PR dans `push_and_create_pr`, avant tout commit ou push, tant que
l'empreinte du contenu du worktree (un arbre git calculé dans un index jetable) est celle qu'il a
lue. Une modification du code rend le verdict périmé ; un commit du même contenu, non. Seul le
bouton « Créer quand même » du dialogue de PR passe outre ; la complétion automatique jamais. Un
fournisseur égal à celui du build est refusé, et le panneau de réglages le signale. La carte
affiche le verdict. Justification : [`cross-review.md`](../../architecture/cross-review.md).

Vérification : `pytest tests/test_cross_review.py -q` et
`cd apps/frontend && pnpm test -- CrossReviewSettings CreatePRDialog worktree-pr-helpers env-utils`.
